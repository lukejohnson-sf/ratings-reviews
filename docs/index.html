Great reviews. Greater Expectations.

Rate Expectations brings ratings, star breakdowns, fit and quality insights, and shopper-written reviews to every product page, from one REST API keyed by your product IDs.

QuickstartAPI Reference →

Overview

SummarizeAverage rating, review count and the 5-to-1 star breakdown.
DisplaySorted, filterable, paginated reviews for the product page.
CollectShopper submissions with validation and fit/quality dimensions.

Base URL: https://ratings-reviews.luke-johnson-c65.workers.dev  ·  JSON  ·  Version v1  ·  Products are keyed by your product ID, so no catalog sync is needed.

Authentication

Send your key in the x-api-key header on every /v1 request. Call from your server only, never from the browser.

x-api-key: rr_••••••••••••••••

Quickstart

# Reviews and summary for a product's page
curl "$BASE/v1/products/P-1001/reviews?sort=highest&limit=4" -H "x-api-key: $KEY"

# Submit a review
curl -X POST $BASE/v1/products/P-1001/reviews -H "x-api-key: $KEY" -H 'content-type: application/json' -d '{
  "rating": 5, "title": "Love these! Cute and a deal",
  "body": "Great quality, good price for the set, and they still look new after many washes.",
  "author": "Jennifer", "location": "Delaware",
  "dimensions": { "fit": 3, "comfort": 5, "quality": 5 },
  "submissionId": "basket-123-P-1001"
}'

Rating summary

GET /v1/products/{productId}/summary returns everything needed for the ratings snapshot block:

{
  "averageRating": 4.6, "totalReviews": 2696, "recommendedPercent": 90,
  "ratingDistribution": [ { "stars": 5, "count": 2024, "percent": 75 }, … ],
  "dimensions": [
    { "id": "fit", "label": "Size & Fit", "type": "scale", "minLabel": "Small", "midLabel": "True to Size", "maxLabel": "Large", "average": 2.9 },
    { "id": "comfort", "label": "Comfort", "type": "rating", "minLabel": "Poor", "maxLabel": "Excellent", "average": 4.6 }
  ],
  "summaryText": "Customers consistently praise the **quality** and **comfort**…"
}

Dimension averages are on a 1–5 scale. For type: "scale" (for example fit), 3 is ideal and the marker sits at the midpoint. For type: "rating", higher is better, so fill bars to average / 5. summaryText marks key themes with **bold**.

Listing reviews

GET /v1/products/{productId}/reviews returns the summary plus a page of reviews, so one call can render the whole section.

QueryValues
sortnewest (default), oldest, highest, lowest
rating1–5, to show only that star level (for example when the 5★ bar is clicked)
limit / offsetPaging; limit max 50, default 10

Each review has id, rating, title, body, author, location, verifiedPurchase, dimensions, createdAt.

Stars on product tiles

GET /v1/summaries?productIds=A,B,C takes up to 50 IDs and returns averageRating and totalReviews for each. Use it on listing and search pages.

Form config

GET /v1/form-config returns the dimension questions (labels, endpoint labels, required flags), the suggested topic chips, and the validation rules. Render the write-a-review form from this config, so a new brand only changes configuration, not code.

Submitting a review

FieldRules
ratingRequired, integer 1–5
titleRequired, max 50 characters
bodyRequired, 50–2000 characters
authorRequired display name, max 40 characters
locationOptional, max 40 characters
dimensionsObject of 1–5 integers. Required keys come from form-config (fit and comfort by default)
customerIdOptional; marks the review verifiedPurchase
submissionIdOptional retry key; a repeat returns the original review with "duplicate": true

Returns 201 with the new review and the updated summary, so you can refresh the page without a second call. The review appears immediately.

Errors

{ "error": { "code": "VALIDATION_FAILED", "message": "One or more fields are invalid",
  "details": { "body": "body must be 50-2000 characters", "dimensions.fit": "fit is required (1-5)" } } }
StatusCodeMeaning
400BAD_REQUESTBad JSON or query parameter
401UNAUTHORIZEDBad or missing x-api-key
422VALIDATION_FAILEDdetails maps each field to its message; show these inline on the form
503SERVICE_UNAVAILABLERetry with backoff; hide the reviews block instead of breaking the page

B2C Commerce integration pattern

  1. Service: create an HTTP service reviews.http in Business Manager, with the API key in the service credential.
  2. Custom SCAPI endpoints: a GET that proxies summary and reviews for a product ID, and a POST that validates the shopper, sets customerId, and forwards the submission through dw.svc.LocalServiceRegistry.
  3. Storefront Next: the PDP loader streams the reviews call so the page renders without waiting for it. A write-a-review dialog posts through an action.
  4. Optional: award loyalty points per approved review (for example with the Perks & Recreation earn endpoint, using the review ID as orderNo).

Testing & chaos

Any product ID returns stable sample data: a star distribution plus 4 sample reviews. Simulate failures with ?chaos=slow (adds 4 seconds), ?chaos=error (returns 503) or ?chaos=flaky (fails 50% of calls), or the x-chaos header. POST /v1/reset removes all submitted reviews.
